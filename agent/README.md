# Attendance Agent

يسحب البصمات من جهاز ZK على الشبكة المحلية ويرسلها للسيرفر على الـ VPS كل بضع دقائق، ويعمل كـ Windows Service.

## قبل التشغيل
1. على الـ VPS: تأكد من وجود `AGENT_API_KEY` في ملف `.env` الخاص بالسيرفر، ثم أعد تشغيل السيرفر.
2. على الجهاز المحلي (نفس شبكة جهاز البصمة): ثبّت Node.js 22 أو أحدث (LTS)، وانسخ مجلد `agent`.
3. انسخ `agent.config.example.json` إلى `agent.config.json` واملأه:
   - `deviceIp` / `devicePort`: عنوان جهاز البصمة (المنفذ الافتراضي 4370).
   - `serverUrl`: رابط السيرفر (يفضل https).
   - `apiKey`: نفس قيمة `AGENT_API_KEY` في السيرفر.
   - `intervalMinutes`: فترة السحب بالدقائق.
   - **أكثر من جهاز بصمة على نفس الكمبيوتر:** بدل `deviceIp` اكتب `devices` (مثال كامل في `agent.config.multi.example.json`):
     ```json
     "devices": [ { "name": "Gate 1", "ip": "192.168.1.201" }, { "name": "Gate 2", "ip": "192.168.1.202", "port": 4370 } ]
     ```
     يسحب من الأجهزة واحدا بعد الآخر. لو جهاز منهم مش متاح، الباقي يكمل والفشل يظهر في اللوج باسم الجهاز (`device Gate 2 failed: ...`). إعداد `deviceIp` القديم لسه شغال زي ما هو، ولو الاتنين موجودين `devices` هو اللي يُستخدم.
   - `since` (اختياري): تاريخ البداية بالشكل `2026-10-01`. أي بصمة قبله على الجهاز تُتجاهل. بدونه تُرسل كل بصمات الجهاز القديمة في أول مرة.
   - `agentName` (اختياري): اسم الفرع أو الكمبيوتر (مثلا `"branch-1"`). بيتبعت للسيرفر مع كل طلب ويظهر في سجل السيرفر، عشان نعرف أنهي فرع بعت. لو مش مكتوب، يُستخدم اسم الكمبيوتر.
   - `schedule` (اختياري): ساعات الدوام الفعلية:
     ```json
     "schedule": { "start": "05:30", "end": "14:30", "idleIntervalMinutes": 60 }
     ```
     داخل الفترة دي يسحب كل `intervalMinutes` (مثلا 5 دقايق)، وخارجها كل `idleIntervalMinutes` فقط (الافتراضي 60 دقيقة). وبيصحى دايما عند بداية الفترة وبعد نهايتها بدقيقة. مفيش بصمة بتضيع خارج الفترة لأن الجهاز نفسه بيحتفظ بها وبتتسحب في أول دورة.
4. `npm install` داخل مجلد `agent`.

## سحب البصمات لملف فقط (أبسط اختبار للاتصال بالجهاز)
```
npm run dump -- 192.168.1.201
```
يسحب كل السجلات من الجهاز زي ما هي (بدون فلترة) ويكتبها في ملف `punches-<IP>-<وقت>.csv` في نفس المجلد. لا يتصل بالسيرفر ولا يخزن أي حاجة. بدون IP يسحب من الأجهزة المكتوبة في `agent.config.json`.

## فحص قبل التشغيل (لا يرسل ولا يخزن شيئا)
```
npm run probe
```
يتصل بالجهاز ويعرض عدد السجلات وأقدم وأحدث بصمة وآخر 5 بصمات، ويتأكد من وصول السيرفر ومن صحة `apiKey`.

## تجربة يدوية
```
npm run once
```
يسحب مرة واحدة ويطبع النتيجة. السجل في `logs/agent.log`.

## التثبيت كخدمة (Administrator)
```
npm run service:install
npm run service:uninstall
```
الخدمة اسمها `AttendanceAgent`، تبدأ مع ويندوز وتعيد التشغيل لو وقعت. من `services.msc` اضبط نوع التشغيل **Automatic (Delayed Start)**، وأوقف الـ Sleep من إعدادات الطاقة.

## القاعدة المحلية (SQLite)
- كل بصمة تُقرأ من الجهاز تُحفظ أولا في ملف `agent.db` بجانب الـ agent، ثم تُرسل للسيرفر، وتُعلَّم "اتبعتت" فقط بعد ما السيرفر يقبلها.
- لو السيرفر أو النت وقع، البصمات تفضل محفوظة محليا وتتبعت أوتوماتيك لما يرجع، حتى لو جهاز البصمة مسح سجله أو اتغيّر.
- لو الجهاز نفسه مش متاح، الـ agent يكمل إرسال المتأخر من القاعدة المحلية ويكتب سبب فشل الجهاز في اللوج.
- المحفوظ والمتبعت يتنضف بعد `retainDays` (الافتراضي 60 يوم) من آخر بصمة، ويُضبط في `agent.config.json`.
- في اللوج: `new` = جديد اتحفظ، `sent` = اتبعت، `waiting` = لسه مستني الإرسال، و`devices 2/3` = كام جهاز اتقرا من الإجمالي.
- مهم: لا تحذف `agent.db` أثناء وجود بصمات `waiting`.

## ملاحظات
- لو السيرفر غير متاح تُعاد المحاولة تلقائيا في الدورة التالية ولا تضيع حركات.
- التكرار آمن: السيرفر يتجاهل أي حركة مكررة.
- `agent.config.json` يحتوي المفتاح السري، لا ترفعه على git.
